# Duet experimental Polyfork board preview

**Checkpoint: primitive preview works; Polyfork integration is blocked and disabled.** This is not a completed asset integration, a playable client, or accessibility acceptance. The three models must not be enabled until their current asset pages and licensing have been read and file loading verified.

## Run locally

From the repository root (Node 20+ and Python 3):

```sh
npm ci --prefix experiments/polyfork-preview
python3 -m http.server 8090 --bind 127.0.0.1 --directory experiments/polyfork-preview
```

Open the served root in a local browser. Use the Position study select and White side / Overhead / Black side buttons. Reset view resets the camera only; Close 3D releases the WebGL resources and leaves all text available. Reopen recreates the scene. Tiles and pieces do not accept moves. No application backend, account, live match, analytics or persistence is added.

This folder is deliberately outside `public/` and `site/`. It is not linked into or copied to existing deployments. No build is required. Its dependencies and lockfile are isolated: three.js **0.180.0**; Playwright **1.56.1** is a development-only browser check. No root dependency or security policy changes.

## Fixtures and visual proposals

`fixtures.mjs` captures the existing public room snapshot shape from `gameNamespace.js:publicRoomState`: `{board, turn, gameOver, winner, playersConnected}`. Pieces retain the existing `{type, color, veiled?, veiled_turns?}` form. The opening board matches `createInitialBoard`; the illustrative e4 Veil flag/counter was generated by existing server `resolveSystems`. Tests compare fixtures to these authoritative outputs. No move validation, AI, rules or new mechanics run in the preview.

Selection is a separate view-only `selectedSquare`, never an invented snapshot field. The selected e2 pawn and Veiled e4 rook have explicit words plus geometric markers; color is supplementary. An always-available piece table and fixture descriptions provide exact positions/states. With no JavaScript, static opening-position text remains available.

One board square is one world unit. Row 0 is rank 8, column 0 is file a: a8 maps to (-3.5, -3.5), h1 to (3.5, 3.5) in X/Z. Camera presets retain these coordinates; overhead puts a8 top-left. The rune's intended position is beside the board at (5.25, 0.06, 0), strictly decoration. It is not rendered while asset loading is disabled.

The prepared loader centers X/Z, grounds minimum Y, and uses a uniform scale bounded by each asset's footprint and height. Repeated tiles/rings share source geometries/materials; per-square parity uses two shared tint sets. Placeholder tokens use shared native geometry. The renderer caps pixel ratio at 1.5, uses no animation loop, and redraws only for view/fixture/resize/loading changes. Resize observers, pending frames, fetches, geometries, textures, materials and the renderer are released when closed or on pagehide. No camera transitions run, including with reduced motion.
