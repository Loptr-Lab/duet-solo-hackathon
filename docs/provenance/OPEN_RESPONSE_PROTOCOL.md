# The Weaver — Open Response Protocol

The original questions were developed in connection with a proposed collaboration. They are now also available as an open framework for people who want to explore the underlying questions from their own perspective.

An independent response is not a response on behalf of the original collaborator, and does not establish agreement with the premises of the questions.

## Response types

1. **Invited Collaborator Response** — a response from the person to whom the original invitation was delivered, entering through the private invitation pathway.
2. **Independent Male Perspective** — a man responding because the structural questions resonate with his own experience. This response represents that respondent only.
3. **Independent Perspective** — any other participant responding from their own experience.
4. **AI-Assisted Response** — a human response where AI was used to help articulate, organize, translate, or edit the person's own thinking.
5. **Anonymous Response** — a response whose public attribution is intentionally withheld.
6. **System / Design Response** — a response from a designer, researcher, artist, or other participant addressing the framework as a system.

## Submission lifecycle

```text
QUESTION
  ↓
PERSONAL RESPONSE
  ↓
AI ASSISTANCE (optional)
  ↓
VERSIONED ARTIFACT
  ↓
PR / ISSUE
  ↓
DISCUSSION
  ↓
CORRECTION / DISAGREEMENT
  ↓
EXPLICIT CONSENT
  ↓
INCORPORATION — IF CHOSEN
```

## Required metadata

Each response should identify, where appropriate:

- response type
- submitter / public attribution
- submission date
- whether AI assistance was used
- questions answered
- questions intentionally skipped
- unresolved questions
- corrections or disagreements
- privacy requests

## GitHub provenance

A Pull Request is preferred when a participant wants a versioned document in the repository. An Issue is appropriate when a participant wants lower-friction discussion before creating a permanent artifact.

The repository should not auto-merge participant responses. A submitted response is not the same thing as accepted project material.

## Corrections and boundaries

Participants may identify:

- a factual error
- an assumption they do not share
- a question that does not apply to them
- something requiring clarification
- something they want removed
- something they want treated as private
- something they want documented differently

The protocol treats disagreement as a legitimate response state.
